# Pre-registration

Written 2026-11-02, after the generator, oracle and split stories and before any detector
or evaluation entry point exists. Do not edit this file; add dated entries under
AMENDMENTS at the bottom instead. The block marked `prereg` below is read by the report
to show expected vs actual.

## What is being compared

Three detectors score each account from its own events (schema: `src/triage_kit/schema.py`):

- **R — rules**: a hand-written YAML rule set (`rules.yaml`), each rule tagged with one
  family. In a split, only rules tagged with a family that the split marks as seen are
  active. Score = 1 − Π(1 − weight) over fired rules; 0 if none fire. Rules encode human
  priors written from the mechanism descriptions; they are not fitted to data.
- **F — feature model**: scikit-learn models on engineered per-account features, trained
  on binary abuse-vs-benign labels of the training accounts (all seen families pooled).
  Four fixed variants, no other settings tried:
  - `lr`: `StandardScaler` + `LogisticRegression(C=1.0, class_weight="balanced", max_iter=2000)`
  - `gb`: `HistGradientBoostingClassifier(max_iter=200, learning_rate=0.1, max_leaf_nodes=15,
    early_stopping=False, random_state=0)`
  - `lr+sim`, `gb+sim`: the same with the template-similarity feature added.
  - **Primary F for winner calls is `gb+sim`.**
- **L — LLM reviewer**: renders an account timeline into a prompt and parses a verdict.
  Offline it uses `MockLLM` (score = a hash of the rendered prompt; family-agnostic,
  label-blind). Mock numbers are plumbing checks, never results.
- **Oracle** (not a detector, lives in `eval/`): knows the planted mechanism; used to
  prove the signal exists and as extra cells in the null control.

### Template-similarity feature (declared before any eval run)

For each account: tokens = `type|b` for each event in time order, where
`b = min(20, floor(log2(1 + seconds since previous event)))` (0 for the first event).
Shingles = the set of consecutive 4-token windows. MinHash signature with 64 seeded hash
functions (fixed salt). Reference population = every account in the dataset being scored
(events only, no labels). Feature value = max over all other accounts of the estimated
Jaccard similarity, multiplied by `n / (n + 20)`, where n = the account's number of
distinct shingles (shrinks short, generic sequences toward 0). This feature was designed
knowing the template-operator mechanism; the report says so.

## Data, seeds and signal levels

- Generator defaults: 5,000 accounts, 60 days, six families (ato, review_ring,
  promo_abuse, scraping, card_testing, template_operator).
- Coordinated families (review_ring, template_operator): 30 groups each per 5,000
  accounts, group size 4–8. **Minimum number of groups per coordinated family: 12**
  (generator health check fails below that). A test cell with **fewer than 10 groups** is
  flagged in the report as "wide CI: few groups".
- Signal levels: s = 0 (null control), **s = 0.5 (primary analysis)**, s = 1 (secondary).
- **Dev seeds: 101, 102, 103** (building, debugging, CI).
- **Eval seeds: 9001 (primary, with bootstrap CIs), 9002 and 9003 (replication, point
  estimates at s = 0.5 only)**. Used only by `make demo` for the final report.

## Splits

Time-ordered by unit: a unit is an account, or a whole group in coordinated families
(timed by its first member). The earliest 60% of units train, the rest test.

- `in_family`: train on all six families, test on all six.
- `heldout_1..3`: train on four families, test on the two unseen ones:
  (template_operator, card_testing), (review_ring, scraping), (ato, promo_abuse).
  Test accounts are the same as in `in_family`.
- A cell = (detector, family, split): test pool = benign test accounts + that family's
  test accounts. Families are evaluated in `in_family` and in the one held-out fold that
  hides them.

## Metrics

- PR-AUC (average precision), always shown with the cell's base rate.
- ROC-AUC (used in the null control).
- Precision and recall at a fixed review budget of **k = 50** accounts (top-k by score).
- 95% intervals from a 1,000-sample stratified cluster bootstrap: abuse units (group for
  coordinated families, account otherwise) and benign accounts are resampled separately.
  Percentile intervals.
- Cost per 1,000 accounts scored: LLM tokens × prices from `config/prices.yaml`
  (placeholder values, clearly marked). Rules and feature model: $0 in API cost.

## What counts as a null, a win and a miss

- A cell whose 95% PR-AUC interval contains the base rate: **no detectable signal**.
- Winner of a family = higher PR-AUC point estimate between R and primary F, at s = 0.5,
  seed 9001. Called **decisive** only if the two 95% intervals do not overlap; otherwise
  "no detectable difference", which matches an expectation of `tie`.
- An expectation that does not hold is reported as a **miss**, not explained away.

## Hypotheses

- H1 (null control): at s = 0, across every detector × family × split cell including the
  oracle, Bonferroni-corrected intervals (alpha = 0.05 / number of cells) contain the base
  rate (PR-AUC) and 0.5 (ROC-AUC).
- H2 (signal): at s = 1 the oracle reaches PR-AUC ≥ 0.9 on every family.
- H3 (held-out drop): for every family, primary F has lower PR-AUC held-out than in-family.
  Reason: features that separate one family (e.g. reviews without purchase) are learned
  only when that family is in training.
- H4 (template feature, in-family): `gb+sim` beats `gb` on template_operator by ≥ 0.10
  PR-AUC at s = 0.5. Reason: template accounts look ordinary one at a time; the evidence
  is cross-account.
- H5 (template feature, held-out): the gain from `+sim` on template_operator is smaller
  held-out than in-family. Reason: with no template accounts in training, nothing teaches
  the model that high similarity means abuse.
- H6 (LLM, **untestable offline**): a real LLM reviewer does best where evidence is in
  readable text and sequences (review_ring, ato) and worst on template_operator, whose
  evidence is cross-account and invisible in a single timeline. It costs far more per
  1,000 accounts than R or F.

Expected winners (R vs primary F, s = 0.5, seed 9001) and why:

| family | in-family | held-out | why |
|---|---|---|---|
| ato | F | F | fail-burst counts are easy to learn; velocity features partly transfer |
| review_ring | F | tie | reviews-without-purchase is learnable; held-out, nothing teaches it |
| promo_abuse | tie | tie | strong human priors (disposable email, codes at signup) match a model |
| scraping | tie | F | extreme volume is trivial for both; held-out F still sees high velocity |
| card_testing | tie | tie | decline bursts are an obvious rule and an obvious feature; held-out both weak |
| template_operator | F | tie | only the similarity feature sees it; held-out both weak |

LLM expectations for every family: **untestable offline**.

## AMENDMENTS

### 2026-11-02 — split timing of groups, and the bootstrap interval for ROC-AUC

Both found by the null-control acceptance test on dev seeds, before any eval-seed run.
No detector, feature or generator setting changed.

1. **Group timing in the split.** The Splits section says a group is "timed by its first
   member". At s = 0 group members have independent benign signup times, so the earliest of
   4–8 members is almost always early and every coordinated group fell into train, leaving
   test cells with zero positives (dev seed 101). Groups are now timed by the signup time of
   their **lowest-account-id member** (ids are random, so this is distributed like a single
   account's signup time). At s > 0 members are created within two days of each other, so
   this barely moves anything.
2. **ROC-AUC intervals get a continuity correction.** With the plain stratified cluster
   bootstrap, the rules' ROC-AUC Bonferroni intervals excluded 0.5 in 5–7 of 84 null cells
   per dev seed: a rule firing on ~3% of benign accounts and on 0 of ~21 abuse accounts in a
   cell (a likely draw under the null) can only produce intervals below 0.5, because no
   resample of 21 zero-score accounts contains a firing. Each class now gets two pseudo-units
   (one above every real score, one below) inside the bootstrap for ROC-AUC, in the spirit of
   Agresti–Coull. PR-AUC keeps the plain bootstrap: applying the same correction to PR-AUC
   pushed its intervals upward (up to 22 of 84 uncorrected and 2 Bonferroni misses on dev seed
   103), because a pseudo-positive at the top adds about 1/(P+2) to average precision.
   Null-control results per dev seed, Bonferroni misses PR-AUC/ROC-AUC (uncorrected 95%
   misses in brackets), of 84 cells: plain 0/5 (4/10), 0/7 (0/11), 0/5 (6/7); correction on
   both 0/0 (16/4), 0/0 (10/3), 2/0 (22/3); chosen, correction on ROC-AUC only: 0/0 (4/4),
   0/0 (0/3), 0/0 (6/3). Seeds 101, 102, 103 in that order; 1,000 bootstrap samples.

### 2026-11-02 (later) — group members on the far side of the time cutoff are excluded

Found by the null control on eval seed 9001, in the first `make demo` run (4 of 84 cells
failed; 3 were coordinated-family cells, e.g. template_operator ROC-AUC 0.37 at s = 0).
Cause, confirmed on dev seeds 101 and 102 (not on the eval seed): a group goes wholly to one
side of the cutoff, but at s = 0 its members have independent signup times, so test group
members were 10–14 days older on average than benign test accounts (all created after the
cutoff), and account age leaked group membership. Fix: a group member whose own signup is on
the other side of the cutoff is excluded from both train and test, so the split is strictly
time-ordered per account and no group straddles it. No generator or detector setting changed.
Null control after the fix, Bonferroni misses of 84 cells: dev 101: 0, dev 102: 0, dev 103: 1
(heldout_1 template_operator gb+sim, ROC-AUC interval upper bound 0.498, a 12-group cell where
the hash-based mock also scores 0.41). Eval seed 9001 was then re-run once; the report says so.

### 2026-11-02 (evening) — post-hoc, after seeing eval-seed results: interval refinements

Requested by the owner after reading the first report. These change how intervals and the
"no signal" reference are computed, not any detector, feature, split or generator setting.
Designed and checked on dev seeds 101–103 only, before the eval seeds were run again.

1. **Few-cluster widening.** Each side of every percentile interval (95% and Bonferroni) is
   widened around the point estimate by `sqrt(n/(n−1)) · t(1−α/2, n−1) / z(1−α/2)`, where n is
   the number of resampled units in the scarcer class of the cell (groups for coordinated
   families). Motivated by Hesterberg's expanded percentile interval: with ~10 groups the plain
   percentile bootstrap is too narrow (one borderline null miss on dev 103). Never narrows.
2. **Null PR-AUC reference.** Each cell also reports the exact expected PR-AUC under random
   labels given the detector's tie structure (hypergeometric moments over tie blocks; equals the
   base rate when everything ties, and exceeds it for a continuous score with few positives).
   The report uses it as the "no detectable signal" reference. The acceptance test against the
   base rate is unchanged; a stricter companion test also requires each non-degenerate null
   cell's corrected interval to contain the null PR-AUC. A cell is **degenerate** when no
   positive scores above the lowest score (PR-AUC equals the base rate and cannot vary).
   Null control with both changes, Bonferroni misses of 84 cells (base rate or ROC 0.5 / null
   PR-AUC): dev 101: 0 / 0, dev 102: 0 / 0, dev 103: 0 / 0 (9, 9 and 6 cells degenerate).
3. Winner calls keep the pre-registered rule (95% CIs overlap → tie); with wider intervals
   some calls may change, and the report shows both the original and the updated outcome.
